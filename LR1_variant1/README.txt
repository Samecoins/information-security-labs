ЛАБОРАТОРНАЯ РАБОТА №1. ВАРИАНТ 1
Python и Windows 11

1. КАК ЗАПУСТИТЬ

Распакуйте весь архив в отдельную папку, например C:\Labs\LR1.
Не запускайте файлы прямо из архива.
Нужен Python 3.10 или новее с tkinter (компонент Tcl/Tk).
Если Python уже установлен, сначала попробуйте выполнить в терминале:
    py --version

Откройте терминал в папке программы (Проводник → адресная строка → cmd).
Запуск:
    py -3 main.py
Или дважды нажмите start.bat.
Если команда py не найдена, а python работает:
    python main.py

Используются только стандартная библиотека Python и встроенный криптопровайдер
Windows. Команды pip install не нужны.

Перед сдачей откройте main.py и замените значение AUTHOR на свои ФИО и группу.

2. ПЕРВЫЙ ЗАПУСК

Сначала придумайте парольную фразу для шифрования всего файла, повторите её.
Запомните её: она потребуется при каждом запуске.
Затем в окне входа введите имя ADMIN, поле пароля оставьте пустым.
Программа предложит установить и подтвердить пароль ADMIN.
Например, для учебной демонстрации можно использовать Admin+123.

Парольная фраза защищает файл всех учётных записей.
Пароль ADMIN нужен для входа в конкретную учётную запись.
Это два разных секрета. Программа не задаёт их заранее.

3. КАК ПРОВЕРИТЬ РАБОТУ

А. Войдите как ADMIN. В меню «Администрирование» добавьте student.
Б. Выберите student в таблице и откройте «Параметры выбранного».
   Установите: блокировка 0, ограничения 1, минимальная длина 8, срок 1 месяц.
В. Закройте программу и запустите снова. Введите прежнюю парольную фразу.
   Войдите как student с пустым паролем — откроется установка пароля.
Г. Попробуйте abc: программа отклонит его. Затем задайте Student+1 и повторите.
   Сохраните скриншот ошибки и скриншот окна обычного пользователя.
Д. Проверьте: у student меню администрирования отключено.
   Доступны смена собственного пароля и выход, а также справка.
Е. Смените пароль: неправильный старый пароль и несовпадающее подтверждение
   должны отклоняться. Отмена обычной смены оставляет старый пароль.
Ж. Перезапустите программу, войдите ADMIN и заблокируйте student.
   При следующем запуске вход student должен быть запрещён.
З. В отдельном запуске введите три неверных пароля существующего незаблокированного
   пользователя. Программа должна завершиться после третьей ошибки.
И. Введите неизвестное имя: получите сообщение и возможность повторного ввода.
К. При запуске введите неверную парольную фразу: программа завершится,
   существующий файл учётных записей не будет перезаписан.
Л. Откройте «Справка → О программе» и сделайте скриншот с вашими ФИО.

В папке проекта также можно выполнить:
    py -3 -m unittest -v
На Windows должны выполниться 10 тестов, включая MD4, DES и запись/чтение файла.
Тесты создают данные во временной папке, ваш accounts.dat не затрагивают.

Проверка срока действия на календарных границах включена в тесты.
В интерфейсе срок задаётся в целых месяцах; 0 означает бессрочно.
После истечения срока правильный старый пароль допускает только к обязательной
смене пароля. Отмена завершает работу. Повтор истёкшего пароля не допускается.
При переносе даты с 31 января на февраль выбирается последний день февраля.

4. ЧТО РЕАЛИЗОВАНО И КАК ЧИТАТЬ КОД

main.py — графический интерфейс tkinter, меню, диалоги, запуск и завершение.
model.py — правила паролей, срок действия, учётные записи и файл.
wincrypto.py — вызовы Microsoft CryptoAPI через ctypes.
test_lab.py — проверка логики и Windows-криптографии.

Для изучения начните с model.py: new_user, password_error, Session.login,
Session.change_password. Затем прочитайте Store.open и Store.save.
После этого изучайте окна в main.py. Низкоуровневый wincrypto.py можно
разбирать последним: он связывает Python с функциями Windows.

Имена чувствительны к регистру: ADMIN и admin — разные имена.
Пробелы по краям имени убираются, пробелы в пароле и фразе сохраняются.
Счётчик неверных паролей общий для текущего окна входа, смена имени его не сбрасывает.
Неизвестное имя и блокировка не считаются неверным паролем.
ADMIN не может блокировать собственную запись.

По умолчанию минимальная длина равна 0, ограничения выключены, срок равен 0.
Поэтому методичка допускает пустой пароль: при первом входе всё равно нужно
пройти форму его установки и подтверждения. Флаг initialized отличает новый
аккаунт от аккаунта, владелец которого подтвердил пустой пароль.
При включённых ограничениях варианта 1 пустой пароль уже не пройдёт проверку.
Минимальная длина проверяется независимо от флага ограничений состава.
Для букв используются islower/isupper: подходят и латинские, и русские буквы.
Арифметическими знаками в программе считаются + - * / =.

5. СТРУКТУРА ХРАНИЛИЩА ДЛЯ ОБЪЯСНЕНИЯ И ОТЧЁТА

accounts.dat находится рядом с main.py, создаётся автоматически.
Формат двоичного файла:
  смещение 0, длина 8: сигнатура IBLR1V1 и нулевой байт;
  смещение 8, длина 16: случайная соль;
  смещение 24, до конца: JSON в UTF-8, зашифрованный DES-ECB с дополнением.
Сигнатура и соль не зашифрованы. Парольная фраза и готовый ключ не записываются.

Расшифрованный JSON имеет поля version и users.
users — словарь, ключами которого служат уникальные имена.
Поля каждой учётной записи:
  password_hash — MD4 пароля, 32 шестнадцатеричных символа;
  initialized — пройдена ли первоначальная установка пароля;
  blocked — заблокирована ли запись;
  restricted — включены ли ограничения варианта 1;
  min_length — минимальная длина;
  months — срок действия в месяцах;
  changed_at — время установки пароля ISO 8601 в UTC, либо null до установки.
У новой записи хранится MD4 пустой строки, а не открытый пароль.

При запуске шифротекст читается с диска, расшифровывается в память и проверяется:
обязательно наличие ADMIN, а также корректность структуры и параметров.
При неверной фразе или повреждении данных вход не открывается.
После каждого изменения и при штатном выходе данные снова шифруются.
Новый шифротекст сначала записывается во временный .accounts-*.tmp рядом с
accounts.dat, затем os.replace заменяет прежнюю версию. Временный файл содержит
только зашифрованные данные; расшифрованный JSON на диск программой не пишется.
При ошибке записи изменение в памяти откатывается. Если не удалось сохранить
при выходе, окно остаётся открытым и показывает ошибку.
accounts.lock предотвращает параллельный запуск двух экземпляров для одной базы;
это служебный файл из одного байта, учётных данных в нём нет.

После выхода освобождаются дескрипторы ключа, хешей и криптопровайдера.
Временные ctypes-буферы затираются. Python не гарантирует полное затирание всех
копий строк в памяти; наличие системного файла подкачки также не контролируется.
os.replace удаляет прежнюю версию на уровне файловой системы, но не гарантирует
физическое уничтожение старых секторов SSD или резервных копий.

6. ХЕШИРОВАНИЕ И ШИФРОВАНИЕ

Провайдер: Microsoft Enhanced Cryptographic Provider v1.0, PROV_RSA_FULL.
CryptAcquireContextW открывает контекст с CRYPT_VERIFYCONTEXT без контейнера ключей.

Хеш пароля:
  пароль → байты UTF-8 → CryptCreateHash(CALG_MD4) → CryptHashData →
  CryptGetHashParam(HP_HASHVAL) → hex-строка.
При входе вычисляется хеш введённого пароля и сравнивается с сохранённым через
hmac.compare_digest. Открытые пароли пользователей в JSON не хранятся.

Ключ шифрования:
  CryptGenRandom создаёт 16 байт соли;
  MD4 вычисляется от salt || UTF8(парольная фраза);
  CryptDeriveKey(CALG_DES) формирует ключ DES с эффективной длиной 56 бит;
  CryptSetKeyParam(KP_MODE, CRYPT_MODE_ECB) выбирает ECB.
Это выбранная реализация требования «добавление к ключу случайного значения»:
случайная соль участвует в формировании ключа. Она не расширяет длину DES-ключа.
Это не флаг CRYPT_CREATE_SALT и не вектор инициализации: в ECB IV не используется.
При чтении берётся сохранённая соль; при записи создаётся новая.

CryptEncrypt с Final=True дополняет данные до границы 8-байтного блока.
CryptDecrypt с Final=True снимает дополнение. Затем JSON проверяется на ADMIN.
Все криптографические операции выполняет провайдер Windows, а не самописный DES.
DES-ECB и MD4 применяются здесь по заданию; это учебная реализация,
а не схема защиты для реальной системы. Отдельного MAC у формата нет.

Официальная документация, использованная при реализации:
https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-cryptderivekey
https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-cryptsetkeyparam
https://learn.microsoft.com/en-us/windows/win32/seccrypto/microsoft-enhanced-cryptographic-provider

7. ЧТО ОСТАЛОСЬ ДЛЯ СДАЧИ

Указать свои ФИО и группу в AUTHOR; запустить программу на своём Windows 11;
выполнить проверки выше; сделать реальные скриншоты.
Для отчёта использовать объяснения из разделов 4–6, добавить листинги .py
с комментариями, свои скриншоты и вывод по результатам выполненных проверок.
Этот архив содержит программу и материал для отчёта, а не оформленный отчёт.

В среде подготовки проверены синтаксис и 7 тестов логики. Три теста Windows
здесь пропущены: CryptoAPI и графический интерфейс Windows нужно проверить
на целевой машине. Успешный запуск на Windows заранее не заявляется.
